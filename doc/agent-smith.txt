1. Introduction                                   *agent-smith-introduction*

Agent-Smith is a Neovim plugin for AI-assisted code editing. It provides
bounded editing where AI only modifies what you select, with explicit
approval for multi-file changes.

Key features:
- Visual selection editing (AI replaces only selected code)
- Disposable provider workspaces under tmp_dir for every request
- Multi-provider support (OpenCode, Claude, Cursor, Gemini, Kiro, Pi)
- Multi-file edits with per-file approval
- Import detection and routing
- AI-planned ripgrep code search with fuzzy Telescope/fzf-lua results and quickfix fallback
- Custom rules (#SKILL.md) and file references (@path)

The core philosophy is user control: no changes happen without your
explicit action.

==============================================================================
2. Requirements                                   *agent-smith-requirements*

- Neovim >= 0.10
- One supported AI CLI in PATH:
  - opencode (https://opencode.ai)
  - claude (https://claude.ai)
- ripgrep (rg) in PATH for codebase search
  - cursor-agent (https://cursor.com)
  - gemini (https://gemini.google.com)
  - kiro-cli (https://kiro.dev)
  - pi (https://github.com/badlogic/pi-mono)

Optional:
- Bubblewrap / bwrap on Linux (read-only original-project mount)
- telescope.nvim (for model/provider pickers)
- fzf-lua (alternative to telescope)
- nvim-cmp or blink.cmp (for enhanced completions)

3. Installation                                   *agent-smith-installation*

With lazy.nvim: >lua
  {
    "your-username/agent-smith.nvim",
    config = function()
      require("agent-smith").setup()
    end,
  }
<

With packer.nvim: >lua
  use {
    "your-username/agent-smith.nvim",
    config = function()
      require("agent-smith").setup()
    end,
  }
<

Manual installation: >bash
  cd ~/.local/share/nvim/site/pack/plugins/start
  git clone https://github.com/your-username/agent-smith.nvim.git
<

4. Setup                                              *agent-smith-setup*

Call setup() once during plugin initialization: >lua
  local smith = require("agent-smith")
  smith.setup({
    provider = smith.Providers.PiProvider,
    -- Pi uses its configured default unless model is set explicitly.
    completion = {
      source = "native",
      custom_rules = { "path/to/rules/" },
    },
    md_files = { "AGENTS.md" },
    -- Must be absolute and outside project. Provider must allow this path.
    tmp_dir = "/tmp/nvim/agent-smith",
    default_keymaps = true,
  })
<

Setup options:                                          *agent-smith-options*

  `provider`        AI provider to use (default: OpenCodeProvider)
  `model`           Model identifier (default: provider's default)
  `logger`          Logger options: { level, path, print_on_error }
  `completion`      Completion config: { source, custom_rules, files }
  `md_files`        Context file names to discover (default: {"AGENTS.md"})
  `tmp_dir`         Absolute temp root outside project for disposable provider
                    workspaces. Agent harness permissions must allow this path.
  `default_keymaps` Set false to disable default keymaps

5. Providers                                         *agent-smith-providers*

Agent-Smith supports multiple AI CLI backends. Each provider implements
the same interface, so switching is seamless.

Available providers:                                    *agent-smith-provider-list*

  `OpenCodeProvider`    Default. Uses opencode CLI.
  `ClaudeCodeProvider`  Uses claude CLI.
  `CursorAgentProvider` Uses cursor-agent CLI.
  `GeminiCLIProvider`   Uses gemini CLI.
  `KiroProvider`        Uses kiro-cli CLI.
  `PiProvider`          Uses pi CLI.

Switching providers: >lua
  -- At setup
  smith.setup({ provider = smith.Providers.PiProvider })

  -- At runtime
  smith.set_provider(smith.Providers.ClaudeCodeProvider)

  -- Via Telescope (if installed)
  vim.keymap.set("n", "<leader>ap", function()
    require("agent-smith.extensions.telescope").select_provider()
  end)
<
Or from the command line: >vim
  :Telescope agent_smith providers
<

Switching models: >lua
  -- At runtime
  smith.set_model("claude-sonnet-4-5")

  -- Via Telescope
  vim.keymap.set("n", "<leader>am", function()
    require("agent-smith.extensions.telescope").select_model()
  end)
<
Or from the command line: >vim
  :Telescope agent_smith models
<

Adding a custom provider:                               *agent-smith-custom-provider*

Create a new file in lua/agent-smith/providers/ with: >lua
  local Base = require("agent-smith.providers").BaseProvider
  local P = setmetatable({}, { __index = Base })

  function P:_get_provider_name() return "MyProvider" end
  function P:_get_default_model() return "my-model" end
  function P:_build_command(query, context)
    return { "my-cli", "--print", query }
  end

  return P
<

Then register in lua/agent-smith/providers/init.lua.

6. Commands                                         *agent-smith-commands*

All operations are accessed via Lua functions: >lua
  local smith = require("agent-smith")
<

  *:AgentSmithVisual*     |smith.visual()|
  Visual selection edit. Select code, invoke, type instructions.
  While request runs, inline spinners render above and below selection.

  *:AgentSmithMultiFile*  |smith.multi_file()|
  Multi-file edit with per-file approval.

  *:AgentSmithSearch*     |smith.search()|
  AI turns natural-language request into PCRE2 patterns from isolated empty
  workspace, then local ripgrep searches project files. Uses Telescope or
  fzf-lua when available and falls back to quickfix.

  *:AgentSmithVibe*       |smith.vibe()|
  Sandboxed two-phase agentic workflow.
  1. Copies current tracked and untracked nonignored project files to a unique
     temporary session directory.
  2. Model inspects the sandbox and returns a plan plus editable file scope.
  3. User approves or rejects plan before execution.
  4. Model executes inside sandbox using only approved paths.
  5. Agent-Smith diffs sandbox against originals and asks approval per file.
  Original files remain untouched until a file proposal is approved.
  Analysis-only results open Quickfix; <CR> opens location, q or Esc closes.

  *:AgentSmithTutorial*   |smith.tutorial()|
  Generate a tutorial in a split window.

  *:AgentSmithProgress*   |smith.progress()|
  Open live request-progress floating window. It lists queued visual edits,
  Vibe planning/execution phases, elapsed time, and latest provider stdout.
  q or Esc closes, r refreshes, x cancels all tracked requests. Visual edits
  also render latest provider stdout above the inline Implementing marker.

  *:AgentSmithCancel*     |smith.stop_all_requests()|
  Cancel all in-flight requests.

  *:AgentSmithLogs*       |smith.view_logs()|
  Browse request history.

  *:AgentSmithInfo*       |smith.info()|
  Show current provider and model.

7. Keymaps                                         *agent-smith-keymaps*

Default keymaps (set default_keymaps = false to disable):

  Visual mode:
    <leader>as    Visual edit (replaces selection)
    <leader>aS    Multi-file edit (with approval)

  Normal mode:
    <leader>af    AI-planned ripgrep search
    <leader>av    Vibe mode
    <leader>ax    Cancel all requests
    <leader>ar    Request progress

Custom keymaps: >lua
  vim.keymap.set("v", "<leader>e", function()
    require("agent-smith").visual()
  end)

  vim.keymap.set("n", "<leader>s", function()
    require("agent-smith").search()
  end)
<

Prompt window keymaps (shown at the bottom of the prompt):
  :write     Submit prompt
  Esc        Close prompt from Normal mode without submitting

Multi-file approval window keymaps:
  <CR>      Approve this file change
  q         Reject this file change
  Q         Reject all remaining changes

8. Completions                                     *agent-smith-completions*

While typing in the prompt window, you can reference:

  #rules      Type # to autocomplete SKILL.md files
  @files      Type @ to autocomplete project files

Rules are SKILL.md files in configured directories. Files are discovered
via git ls-files.

Completion sources:                                    *agent-smith-completion-sources*

  `native`    Built-in omnifunc (default, no dependencies)
  `cmp`       nvim-cmp source (requires hrsh7th/nvim-cmp)
  `blink`     blink.cmp v1 custom source

Blink configuration: >lua
  sources = {
    per_filetype = {
      ["agent-smith-prompt"] = { "agent_smith" },
    },
    providers = {
      agent_smith = {
        name = "Agent-Smith",
        module = "agent-smith.extensions.blink",
        score_offset = 100,
      },
    },
  }
<

The source only runs in Agent-Smith prompt buffers. Type `#` for indexed
SKILL.md files or `@` for indexed project files. Accepting an item inserts
its reference; submitting the prompt injects the referenced content.

Configuration: >lua
  smith.setup({
    completion = {
      source = "native",  -- or "cmp" or "blink"
      custom_rules = { "path/to/rules/" },
    },
  })
<

9. Multi-File Edits                                *agent-smith-multi-file*

Multi-file edits let the AI propose changes across multiple files. Each
change is presented for approval before application.

Protocol:                                              *agent-smith-multi-file-protocol*

The AI outputs structured blocks: >text
  <FILE_CHANGE>/absolute/path/to/file.lua</FILE_CHANGE>
  <CONTENT>
  -- full replacement content for this file
  </CONTENT>
<

Approval flow:
1. Each file change opens a "Change Proposal" review window
2. Neogit-inspired panel opens with unified diff and unchanged context; no change is applied yet
3. User presses Tab to toggle unified diff and full proposed file content
4. User presses <CR> (apply), q or Esc (skip), or Q (skip all)
5. Approved changes are written to disk
6. Staleness detection warns if file changed during approval

Usage: >lua
  -- Via keymap (visual mode)
  <leader>aS

  -- Via API
  smith.multi_file()

  -- With additional_prompt
  smith.multi_file({
    additional_prompt = "Extract this function to utils.lua",
  })
<

10. Import Handling                                  *agent-smith-imports*

When the AI response contains import statements, they are automatically
routed to the file's import section instead of the visual selection.

Supported languages:
- Lua: local X = require("..."), require("...")
- TypeScript/JavaScript: import X from "...", const X = require("...")
- Python: import X, from X import Y
- Ruby: require "...", require_relative "...", use X
- Go: import "...", import ( ... )

Example:
1. Select a function body
2. Type "use the debounce utility from utils"
3. AI response contains:
   - Import: local debounce = require("utils").debounce
   - Code: debounce(fn, 300)
4. Import is placed at file top, code replaces selection

12. Configuration                                 *agent-smith-configuration*

AGENTS.md discovery:                            *agent-smith-agents-discovery*

The plugin automatically discovers AGENTS.md files from the current
file's directory up to the git root. This provides hierarchical project
context.

Example structure: >text
  project/
  ├── AGENTS.md           (project-wide rules)
  ├── src/
  │   ├── AGENTS.md       (src-specific rules)
  │   └── api/
  │       └── AGENTS.md   (api-specific rules)
<

All three files are injected when editing files in src/api/.

Custom context files:                             *agent-smith-custom-context*

Configure additional context files: >lua
  smith.setup({
    md_files = { "AGENTS.md", "CONVENTIONS.md", "PATTERNS.md" },
  })
<

Custom rules:                                       *agent-smith-custom-rules*

SKILL.md files provide project-specific context: >text
  rules/
  ├── vim/
  │   └── SKILL.md      (accessed as #vim)
  ├── python/
  │   └── SKILL.md      (accessed as #python)
  └── cloudflare/
      └── SKILL.md      (accessed as #cloudflare)
<

Configuration: >lua
  smith.setup({
    completion = {
      custom_rules = { "rules/" },
    },
  })
<

Usage in prompt: >text
  #vim Add error handling following vim conventions
<

14. Architecture                                   *agent-smith-architecture*

Request lifecycle:                                 *agent-smith-lifecycle*

  1. User invokes operation (visual/search/vibe)
  2. Prompt window opens for instructions
  3. User types, presses Ctrl-Enter or :write to submit
  4. Context assembled:
     - AGENTS.md files from directory hierarchy
     - Operation-specific system prompt
     - User instructions
     - Current file path
     - Resolved #rules and @files
  5. Project copied to a unique disposable workspace under tmp_dir
  6. Provider CLI spawned asynchronously with disposable workspace as cwd
  7. Progress view receives queued/running phase and latest provider stdout
  8. Response paths remapped to original project; workspace deleted
  9. Parsed and applied:
     - Visual: imports extracted, selection replaced
     - Search: fuzzy location picker opened (quickfix fallback)
     - Multi-file: approval flow per file

Non-Vibe request sandbox:                    *agent-smith-request-sandbox*

  - Every non-Vibe provider request runs from a unique project copy under tmp_dir
  - Provider-side relative writes affect only disposable workspace
  - Response paths are remapped from workspace to original project
  - Workspace is deleted before operation handles provider response
  - Pi disables mutating tools for non-Vibe operations; OpenCode uses its plan
    agent, while disposable workspace remains containment boundary
  - On Linux with Bubblewrap (bwrap), canonical project path is mounted
    read-only, blocking writes through that path even if provider invokes tools
  - Without Bubblewrap, provider CLI retains normal host permissions; only
    project-relative writes are isolated by disposable cwd

Sandboxed Vibe lifecycle:                      *agent-smith-vibe-sandbox*

  - Session root uses a unique system temporary directory
  - Project files are copied; originals are never moved
  - Git repos copy tracked plus untracked nonignored files
  - Plan paths must be repository-relative and cannot escape sandbox
  - Sandbox is recreated from originals after plan approval, discarding any
    plan-phase mutations before execution starts
  - Changes outside approved plan scope are ignored and reported
  - Sandbox is deleted after completion, cancellation, or failure
  - New, modified, and deleted files use the same diff approval panel

Provider contract:                              *agent-smith-provider-contract*

All providers implement:
  `_build_command(query, context)`  Build CLI command array
  `_get_provider_name()`           Return display name
  `_get_default_model()`           Return default model ID
  `fetch_models(callback)`         List available models (optional override;
                                   base implementation reports unsupported)

The Pi provider discovers configured models with `pi --list-models`.

State management:                                   *agent-smith-state*

Single State singleton holds:
- Current provider and model
- Provider override (runtime switching)
- Discovered rules and context files
- Request tracking history
- Completion configuration

15. Troubleshooting                               *agent-smith-troubleshooting*

"Provider not configured":                      *agent-smith-error-provider*

  Ensure setup() is called with a valid provider:
  >lua
    smith.setup({ provider = smith.Providers.OpenCodeProvider })
  <

"Select code first":                          *agent-smith-error-selection*

  You must be in visual mode and have text selected before invoking
  visual() or multi_file().

"Request failed":                                *agent-smith-error-request*

  Failure notifications include a diagnostic block containing:
  - Cause and provider name
  - Configured model
  - Executable availability
  - Working directory
  - Whether the prompt argument reached the command
  - Exit code and signal
  - Provider stderr

  Prompt text is always redacted from diagnostics.

  Check:
  1. Provider CLI is installed and in PATH
  2. Provider CLI is authenticated (if required)
  3. Configured model exists in the provider model list
  4. Network connection (if using cloud providers)
  5. Read stderr in the failure notification

No code search results:                      *agent-smith-error-quickfix*

  The AI response didn't match the expected location format. Try:
  1. Rephrase your search query
  2. Use a different model
  3. Check provider logs

Multi-file changes not applied:          *agent-smith-error-multi-file*

  Ensure the AI output includes proper FILE_CHANGE/CONTENT blocks.
  Not all models handle the multi-file format equally well.

Import not detected:                        *agent-smith-error-imports*

  Only single-line imports are detected. Multi-line imports like:
  >lua
    local foo = require("bar").baz
  <

  are detected, but:
  >lua
    local foo = require("bar")
      .baz
  <

  are not.
